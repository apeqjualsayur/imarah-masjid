# Phase 2 module: Sambungan AI (MCP)

Decisions (owner, 2026-11-25): users connect their OWN AI (Claude, ChatGPT or any MCP-capable client) to Imarah through an MCP server. Available to any user with access, on any plan. Version 1 is READ-ONLY. Draft-writing tools come later (not in this spec). Not validated with pilots yet: ask them after Phase 1 is in use.

## 1. Goal
A signed-in user can authorise their own AI to look up the masjid information that user is already allowed to see, and ask questions in Malay or English. The AI never changes anything.

## 2. Principles
1. The AI acts as the user: same masjid, same role, same visibility as in the app. Nothing extra.
2. Read-only. No tool writes tenant data. The AI can never approve, lock, post money, send messages or change settings.
3. The system stays the source of truth. Official reports are still generated by Imarah, not by an AI.
4. Off by default per masjid. The Pengerusi switches it on once.
5. Least data: phone numbers and IC digits are hidden from the AI by default; no bulk export of personal data.
6. Everything is audited and can be revoked instantly.

## 3. Architecture
- Endpoint: `https://app.imarahmasjid.my/mcp` (a route in the Next.js app), Streamable HTTP transport, built with the official MCP TypeScript SDK. Before building, check the latest MCP specification and its authorization requirements and follow the current version.
- Sign-in: OAuth 2.1 authorization code with PKCE, with the metadata endpoints MCP clients expect. The consent screen (Bahasa Malaysia) shows the client name, the masjid, the user's role and what it can read. Access tokens are short-lived with refresh tokens; store only hashes.
- Data access: every data query must run under the signed-in user's identity so row-level security applies. The service-role key may be used only for the OAuth and MCP bookkeeping tables, never to read tenant data. In plan mode, propose the safest way to do this and wait for approval.
- Tool list is filtered by role: a tool the user cannot use is not listed.

## 4. Data
| Table | Purpose |
|---|---|
| mcp_clients | Registered AI clients: client_id, name, redirect URIs |
| mcp_grants | user_id, masjid_id, client_id, scopes (`imarah:read`), created_at, last_used_at, revoked_at |
| mcp_tokens | Hashed access and refresh tokens, expiry, grant_id |
| mcp_calls | Audit of each call: user, client, tool, argument summary WITHOUT personal data, row count, time, result status |
| masjids (new columns) | mcp_enabled (default false), mcp_share_sensitive (default false) |
All tables follow the Phase 1 rules: masjid_id, RLS, audit trigger, isolation tests.

## 5. Version 1 tools (all read-only, max 50 rows, paginated)
| Tool | Returns | Roles |
|---|---|---|
| get_masjid_info | Name, state, plan, locked months | All |
| get_fund_balances | Balance per fund, optional as-of date | Pengerusi, Bendahari, Setiausaha, AJK, Imam (totals only) |
| search_transactions | Ledger entries by fund, category, dates, amount range, text | Pengerusi, Bendahari, Setiausaha (view), AJK (view) |
| get_collection_status | Friday collections and their status | Pengerusi, Bendahari, AJK |
| get_month_status | Open or locked, pending items | Pengerusi, Bendahari, Setiausaha |
| list_khairat_arrears | Households in arrears for a year, amounts | Pengerusi, Bendahari, Setiausaha |
| find_household | Max 10 matches, name and khairat status; phone and IC hidden unless the masjid allowed sharing AND the role may see them | Pengerusi, Bendahari, Setiausaha |
| list_meetings and get_minutes | Approved minutes only, visibility respected (omit these tools if the Meetings module is not built) | Per meeting visibility |
| list_action_items | Open actions by owner and status | Per roles |
| get_report_preview | Summary numbers of a report for a LOCKED month, not the file | Pengerusi, Bendahari, Setiausaha |
Amounts are returned as sen and as a formatted "RM x,xxx.xx" string.

## 6. Security rules
- Untrusted text (minutes, notes, descriptions, names) is data, not instructions. Wrap it in clear markers, truncate long fields, strip control characters, and say so in the tool descriptions.
- No tool sends data anywhere, fetches URLs or writes anything. A test fails the build if an MCP handler imports a write function.
- Rate limits per user per minute and per day, set by plan in `lib/plans.ts` (hypotheses: Asas lowest, Standard and Pro higher).
- Disabled automatically when the masjid switch is off, the user is deactivated, or the grant is revoked; revocation takes effect on the next call.
- No personal data in logs or Sentry. The `mcp_calls` argument summary excludes names and phone numbers.
- Never accept masjid_id from the AI client; derive it from the grant.

## 7. Screens
Settings > Sambungan AI. Pengerusi: master switch, option to share sensitive fields (off), list of connected users and clients with last used and Revoke, call log. Every user: "Sambungan saya" with connected AIs, revoke, and "Cara sambung" step-by-step for Claude and ChatGPT (verify current steps before writing), plus sample questions in Malay.

## 8. Plans
Any plan. Per-plan rate limits only.

## 9. Not in version 1
Writing tools (draft minutes, add action), approvals of any kind, money actions, file access, sending messages, an AI assistant built into the app.
